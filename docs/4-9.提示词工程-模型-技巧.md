# 提示词工程

## 1：提示词工程概论

### 核心概念

将模型当作**黑盒**，只关注输入与输出。

### 四类提示词

1. **System Prompt**（系统提示词）
2. **User Prompt**（用户提示词）
3. **Assistant Prompt**（助手提示词）
4. **Tool Prompt**（工具提示词）

### 什么是提示词工程？

**定义**：通过不断优化输入，提升模型输出（Assistant Prompt）的质量

### 三个评价维度

#### 1. 质量维度
- 输出内容的专业、完整和有价值
- 让人感觉"说到点子上"

**编码场景示例**：
```javascript
// ❌ 差的示例
function calc(a, b) {
  return a + b;
}

// ✅ 好的示例
/**
 * 计算两个数字的和
 * @param {number} a - 第一个数字
 * @param {number} b - 第二个数字
 * @returns {number} 两数之和
 * @throws {TypeError} 参数必须为数字类型
 */
function add(firstNumber, secondNumber) {
  if (typeof firstNumber !== "number" || typeof secondNumber !== "number") {
    throw new TypeError("参数必须为数字类型");
  }
  return firstNumber + secondNumber;
}
```

#### 2. 稳定性维度
- 在不同场景和时间下产生可预期的一致表现
- 让人感觉"靠得住"

**编码场景示例**：
```javascript
// ❌ 差的示例：有时直接返回代码，没有包装在JSON中，格式不可预期
function sum(a, b) {
  return a + b;
}

// ✅ 好的示例：返回格式稳定
{
  "language": "javascript",
  "description": "求和函数",
  "code": "function sum(a, b) {\n  return a + b;\n}"
}
```

#### 3. 正确性维度
- 信息的准确度和可信度
- 不产生虚假或误导性内容
- 让人感觉"说的对"

## 2：用专业知识明确需求

### 核心问题

**Q**：不会编程也可以用 AI 工具生成应用，程序员和大众的区别在哪？

**A**：专业知识的深度和对最佳实践的理解

### 基本概念

#### 提示词是什么？

```
提示词 = 用【提示词技巧】表达【明确的需求】
```

#### 明确的需求是什么？

```
明确的需求 = 用【专业知识】探索【特定场景】下的【最佳实践】
```

### 实战案例分析

#### 案例：wuxia-comment 项目

**原始需求**：用武侠故事情节为代码添加注释

**特定场景**：注释生成场景

**探索最佳实践**：
- **Q**：注释和什么关联？
- **A**：和代码逻辑关联
- **结论**：只需将代码逻辑与故事情节映射即可

**优化后的 User Prompt**：
```
我的需求是"用武侠故事情节为代码添加注释"，
我认为需求的最佳实践是"将代码逻辑与故事情节映射"。

请基于最佳实践给出完整实现步骤
```

### AI 辅助编码

**探索最佳实践**：
- **常规思路**：多模态大模型可以识别图片，直接上传设计稿
- **问题**：生成效果不理想
- **专业思路**：
  1. 分析设计稿的布局结构
  2. 识别可复用的组件模式
  3. 确定响应式断点
  4. 明确交互逻辑
  5. 指定技术栈和样式方案

## 3：选择合适的模型

### 模型选择的重要性

不同的模型在不同场景下表现差异巨大，选择合适的模型是提示词工程的关键环节。

### 模型分类

#### 按开源程度分类

1. **闭源模型**
   - OpenAI GPT-4/GPT-3.5
   - Claude (Anthropic)
   - Gemini (Google)
   
2. **开源模型**
   - Llama 系列
   - Mistral
   - Qwen（通义千问）

#### 按能力特点分类

1. **通用对话模型**
   - 适合：日常对话、内容创作、知识问答
   
2. **代码专精模型**
   - 适合：代码生成、代码解释、bug修复
   - 示例：CodeLlama, DeepSeek Coder
   
3. **多模态模型**
   - 适合：图文理解、视觉问答
   - 示例：GPT-4V, Claude 3

### 模型选择策略

#### 考虑因素

1. **任务类型**
   - 创意写作 → 通用大模型
   - 代码生成 → 代码专精模型
   - 图片理解 → 多模态模型

2. **质量要求**
   - 高质量 → 闭源顶级模型（GPT-4, Claude）
   - 平衡性价比 → 中等模型或开源模型

3. **响应速度**
   - 实时交互 → 小型快速模型
   - 批量处理 → 可选大型模型

4. **成本预算**
   - 高频调用 → 考虑开源或小型模型
   - 关键任务 → 投入使用顶级模型

5. **隐私安全**
   - 敏感数据 → 本地部署开源模型
   - 一般数据 → 可用云端服务

### 实践建议

#### 模型测试流程

1. **准备测试集**：收集典型任务样本
2. **多模型对比**：同一提示词测试不同模型
3. **评估维度**：质量、速度、稳定性、成本
4. **记录结果**：建立模型性能数据库

#### 组合使用策略

```
路由策略：
- 简单任务 → 小模型（快速、便宜）
- 复杂任务 → 大模型（高质量）
- 代码任务 → 代码模型（专业）
```

## 4：提示词技巧

### 核心技巧清单

#### 1. 角色设定（Role Playing）

**原理**：为 AI 设定特定身份，引导其从特定视角回答

**示例**：
```
❌ 不好的提示词：
解释一下量子计算

✅ 优化后的提示词：
你是一位资深的量子物理学教授，请用通俗易懂的方式
向大学新生解释量子计算的基本原理
```

#### 2. 任务分解（Task Decomposition）

**原理**：将复杂任务拆解为多个简单步骤

**示例**：
```
❌ 不好的提示词：
帮我写一个完整的电商网站

✅ 优化后的提示词：
我需要开发一个电商网站，请按以下步骤协助：
1. 首先分析需要哪些核心功能模块
2. 然后设计数据库表结构
3. 接着规划前端页面结构
4. 最后给出技术栈建议
```

#### 3. 示例引导（Few-Shot Learning）

**原理**：提供示例帮助 AI 理解期望的输出格式

**示例**：
```
请将以下句子改写为正式的商务邮件语气：

示例1：
输入：能不能明天给我回复？
输出：期待您明日的回复，谢谢。

示例2：
输入：这个方案不行
输出：经过评估，该方案可能需要进一步优化

现在请改写：
输入：你的报告写得太烂了
```

#### 4. 约束条件（Constraints）

**原理**：明确限制条件，避免输出偏离预期

**示例**：
```
✅ 好的提示词：
请用 Python 实现一个排序算法，要求：
- 使用快速排序
- 包含详细注释
- 时间复杂度分析
- 代码不超过50行
- 不使用任何第三方库
```

#### 5. 输出格式指定（Format Specification）

**原理**：明确要求输出的结构和格式

**示例**：
```
请分析这段代码的问题，并按以下 JSON 格式输出：

{
  "issues": [
    {
      "line": "行号",
      "type": "问题类型",
      "description": "问题描述",
      "suggestion": "修改建议"
    }
  ],
  "summary": "总体评价"
}
```

#### 6. 上下文提供（Context Providing）

**原理**：提供充分的背景信息

**示例**：
```
✅ 好的提示词：
背景：我是一家初创公司的技术负责人，团队有5人，
主要做 SaaS 产品，目前使用 React + Node.js 技术栈

问题：我们需要选择一个状态管理方案，
请对比 Redux、MobX、Zustand 的优缺点，
并给出针对我们团队的推荐
```

### 高级技巧

#### 7. 思维链（Chain of Thought, CoT）

**原理**：引导 AI 展示推理过程，提高复杂问题的准确性

**示例**：
```
❌ 直接提问：
一个商店有23个苹果，卖出去15个，又进货30个，
然后卖出去18个，现在还有多少个？

✅ 使用 CoT：
一个商店有23个苹果，卖出去15个，又进货30个，
然后卖出去18个，现在还有多少个？

请按以下步骤思考：
1. 列出每一步的计算
2. 说明每步的逻辑
3. 给出最终答案
```

**效果对比**：
- 不使用 CoT：可能直接给出错误答案
- 使用 CoT：会展示完整推理过程，准确率显著提升

#### 8. 自我一致性（Self-Consistency）

**原理**：让 AI 多次生成答案，选择最一致的结果

**示例**：
```
请用3种不同的方法解决这个问题，
然后对比这些方法的结果是否一致：

问题：[具体问题描述]
```

#### 9. 反思提示（Reflection Prompting）

**原理**：让 AI 检查和改进自己的输出

**示例**：
```
第一步：请生成一个用户注册功能的代码

第二步：请检查上面的代码，思考：
1. 是否有安全漏洞？
2. 是否有性能问题？
3. 是否符合最佳实践？

第三步：基于检查结果，给出改进版本
```

#### 10. 迭代优化（Iterative Refinement）

**原理**：通过多轮对话逐步完善输出

**示例**：
```
第1轮：请设计一个博客系统的数据库结构

第2轮：很好，现在请添加评论功能的表结构

第3轮：请考虑如何支持多级评论（评论的评论）

第4轮：请添加索引优化查询性能
```

#### 11. 对比分析（Comparative Analysis）

**原理**：要求 AI 对比多个选项

**示例**：
```
请对比以下三种方案的优缺点，并给出推荐：

方案A：使用 REST API
方案B：使用 GraphQL
方案C：使用 gRPC

对比维度：
1. 开发效率
2. 性能表现
3. 学习成本
4. 生态支持
5. 适用场景
```

#### 12. 负面提示（Negative Prompting）

**原理**：明确告诉 AI 不要做什么

**示例**：
```
请生成一篇关于健康饮食的文章

要求：
✅ 要包含科学依据
✅ 要通俗易懂
❌ 不要推荐任何保健品
❌ 不要使用夸张的表述
❌ 不要包含未经证实的说法
```

### 组合技巧应用

#### 综合案例：代码审查助手

```
# 角色设定
你是一位有10年经验的高级前端工程师，擅长代码审查

# 任务分解
请按以下步骤审查这段代码：

# 上下文
项目背景：React + TypeScript 项目，使用 Ant Design 组件库

# 思维链
审查步骤：
1. 检查代码规范（命名、格式、注释）
2. 分析逻辑正确性
3. 评估性能影响
4. 识别安全隐患
5. 提出优化建议

# 输出格式
请按以下 JSON 格式输出：
{
  "score": "评分（1-10）",
  "issues": [
    {
      "category": "问题类别",
      "severity": "严重程度（高/中/低）",
      "description": "问题描述",
      "suggestion": "修改建议",
      "example": "示例代码"
    }
  ],
  "summary": "总体评价"
}

# 约束条件
- 每个问题必须给出具体的代码示例
- 建议必须可执行
- 不要使用模糊的表述

# 负面提示
- 不要只指出问题而不给解决方案
- 不要使用过于专业的术语

# 代码内容
[在这里粘贴要审查的代码]
```

## 最佳实践总结

### 提示词工程的核心公式

```
优秀的提示词 = 明确的需求 + 合适的模型 + 有效的技巧

其中：
- 明确的需求 = 专业知识 + 场景理解 + 最佳实践
- 合适的模型 = 任务匹配 + 性能平衡 + 成本考量
- 有效的技巧 = 结构化 + 示例化 + 约束化
```

### 提示词优化流程

1. **明确目标**：清晰定义要解决的问题
2. **分析场景**：理解具体的应用场景
3. **选择模型**：根据任务特点选择合适的模型
4. **设计提示词**：应用合适的技巧组合
5. **测试评估**：从质量、稳定性、正确性三个维度评估
6. **迭代优化**：根据结果持续改进

### 常见问题与解决方案

#### 问题1：输出不稳定

**解决方案**：
- 使用结构化输出（JSON/XML）
- 提供明确的格式示例
- 增加约束条件
- 降低 temperature 参数

#### 问题2：输出质量不高

**解决方案**：
- 增加角色设定
- 提供更多上下文
- 使用思维链引导
- 尝试更强大的模型

#### 问题3：理解偏差

**解决方案**：
- 提供具体示例
- 使用负面提示
- 任务分解细化
- 增加反思环节

#### 问题4：响应速度慢

**解决方案**：
- 简化提示词
- 减少不必要的要求
- 使用更快的模型
- 考虑流式输出

## 进阶资源

### 评估标准

每次使用提示词后，从以下维度评估：
- ✅ **质量**：输出是否专业、完整、有价值？
- ✅ **稳定性**：多次运行结果是否一致？
- ✅ **正确性**：信息是否准确可靠？
- ✅ **效率**：响应速度是否满足需求？
- ✅ **成本**：token 消耗是否合理？

## 附录：术语表

- **System Prompt**：系统级提示词，定义 AI 的基本行为
- **User Prompt**：用户输入的提示词
- **Assistant Prompt**：AI 的输出响应
- **Temperature**：控制输出随机性的参数（0-1）
- **Token**：模型处理文本的基本单位
- **Few-Shot**：提供少量示例的学习方式
- **Zero-Shot**：不提供示例的直接推理
- **CoT**：Chain of Thought，思维链
- **RAG**：Retrieval-Augmented Generation，检索增强生成

## 结语

提示词工程是一门实践性很强的技能，需要：

1. **专业知识**：深入理解所在领域的最佳实践
2. **技术理解**：了解模型的能力和局限
3. **持续实践**：通过大量实践积累经验
4. **迭代思维**：保持优化和改进的意识

记住核心原则：**明确需求 + 合适模型 + 有效技巧 = 优秀输出**
